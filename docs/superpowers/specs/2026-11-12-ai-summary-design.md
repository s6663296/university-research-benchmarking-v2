# AI 簡報總結與跨期比較：設計

日期：2026-11-12
狀態：草稿，待使用者核可

## 1. 目的與緣由

系統已經能產出每個系所的簡報（pptx）和 Excel，也保存了每次分析的版本。但簡報裡只有數字和表格，長官要自己看出「這個系強在哪、弱在哪、跟上一期比是進步還是退步」。原設計文件把「AI 功能」列為待確認（廠商與預算未定），現在已確定使用 Claude，並且已有 API key。

這個功能用 Claude 把分析結果寫成**可以直接交給長官的文字總結**，並在有前期資料時說明各指標的升降。

## 2. 產出

### A｜系所總結頁（每份系所 pptx 的最後一頁）

- 統整這份簡報的全部內容：計畫經費（有匯入經分表時）、論文指標排名、各指標比較。寫出強項，以及「可以努力的方向」。
- 有前期資料時，多一段「與前期比較」：哪些指標進步、哪些退步，附上前後數值或名次。
- 沒有前期資料時，只寫總結，並註明「無前期資料可比較」。系統剛開始使用時都會是這種情況，屬於正常狀況。
- 每個系所的文字只談該系所，不評論其他系所。

### B｜全院總結（獨立下載的檔案）

- 把這次分析的所有系所放在一起看：哪些系所領先、哪些有成長空間、全院整體表現與趨勢。
- 有前期資料時，同樣說明跨期變化。
- 不放進任何系所的簡報，在結果頁另外提供下載，由研發處決定要給誰看。
- 檔案格式：Word（docx），因為內容是文字報告。**（我的判斷）**
- 如果一次分析涵蓋多個學院，每個學院各寫一節。**（我的判斷）**

## 3. 語氣（使用者明確要求）

- 對象是系所主管和校內長官，不能寫得太尖銳。要以中央大學的立場，用長官可以接受的方式潤飾過。
- 進步的地方具體寫出來。落後的地方寫成「仍有成長空間」或「可持續努力的方向」，不寫「嚴重落後」「表現不佳」這類字眼。
- 正式的中文書面語，使用繁體中文與台灣用語。
- 這些語氣規則寫在送給 Claude 的系統提示裡，同時存成一個可以在「設定」頁修改的提示範本。**（我的判斷）**

## 4. 跟哪一期比較（使用者決定）

- **預設自動挑選**：同一系所、上一個期間（例如這次是 2022–2026，就找 2021–2025）裡最後一次完成的分析。
  - 找不到剛好上一年的期間時，改用比這次早、最接近的期間。**（我的判斷）**
  - 以系所為單位比對：只要前一次分析包含這個系所就可以拿來比較，不要求兩次分析的系所範圍完全相同。**（我的判斷）**
  - 同期間重跑的分析不當作前期。
- **承辦人可以改選**：結果頁有一個下拉選單，可以改成任何一次已完成的歷史分析。改選後重新產生文字。
  - 下拉選單整次分析共用一個選擇。改選的那次分析裡沒有的系所，視為「無前期資料」，不會再自動補挑。**（我的判斷）**
  - B 的跨期比較：自動模式下，每個系所各自使用自動挑到的前期；改選模式下，全部系所都使用改選的那次分析。**（我的判斷）**
- **比較內容**：包含各指標的數值和名次。`compare_runs` 目前只比較數值，需要擴充成也比較 `Result.rank`，這是擴充現有函式，不是另寫一套計算。計畫經費的前期數字，用現有的 `funding_table` 和前期年度的經分表算出；前期年度沒有經分表時，經費部分不做比較。**（我的判斷）**
- **比較基準不同時要附註**：前後兩期的對標學校、教師數學年度或自我引用處理方式不同時，文字裡要附註「比較基準不同」，避免把基準改變誤讀成系所退步。**（我的判斷）**
- 數值差異沿用現有的 `app/runs/compare.py`（`compare_runs`），不另寫一套計算。

## 5. 數字的正確性（反目標：AI 寫錯數字）

- 送給 Claude 的資料全部從資料庫取得，也就是 `Result`、`RunUnit`、經費表和 `compare_runs` 的輸出，內容與簡報上的數字相同。不讓 Claude 去讀 pptx 檔。
- 提示裡要求 Claude 只能引用提供的數字，不自行計算新的數字。
- 有「待人工確認」（`Anomaly` 狀態為 open）的項目要告訴 Claude，文字中不可以把它當作結論。
- 數字一律四捨五入到小數第二位，和簡報一致。

## 6. 人工審閱流程（使用者已確認）

1. 分析完成後，結果頁出現「AI 總結」區塊，承辦人按下「產生 AI 總結」才會呼叫 Claude，不會自動執行，以免花不必要的費用。
   - 按一次會產生這次分析所有系所的 A，再加上 B。一次分析可能有幾十個系所，所以在背景執行並顯示進度，做法比照現有的 `app/runs/manager.py`。單一系所可以個別重新產生。**（我的判斷）**
   - 每段文字都記下產生時的輸入資料指紋（例如送給 Claude 的資料的雜湊值）。之後如果資料改變（換了經分表、處理了待人工確認的項目、改了教師數），結果頁會提示「資料已更新，總結可能過時」。重新產生之前，下載的簡報不放入過時的總結頁。人工修改過的文字也一樣，因為數字不一致就違反了反目標。**（我的判斷）**
2. 產生的文字顯示在網頁上，承辦人可以直接修改，也可以「重新產生」。
3. 存檔後的文字（包含人工修改）存在資料庫，跟著該次分析保存，之後回看歷史版本也看得到。
4. 下載簡報時，如果已經有存檔的 A 文字，就放進最後一頁；沒有的話，簡報維持原本的內容，不加這一頁。
5. 下載 B 時，使用存檔的 B 文字產生 docx。

## 7. 技術選擇

- **模型供應商**：Claude（使用者決定）。
- **API key**：`.env` 新增 `ANTHROPIC_API_KEY`，做法比照現有的 `ELSEVIER_API_KEY`（`app/config.py`、`save_env`、設定頁）。不寫進程式碼或資料庫。
- **SDK**：官方 `anthropic` Python 套件，加進 `pyproject.toml`。
- **模型**：預設 `claude-opus-5-5`，可以在「設定」頁更換。**（我的判斷）**
- **產生 docx**：使用 `python-docx`（新的相依套件）。**（我的判斷）**
- **簡報頁面**：沿用 `app/reports/pptx_report.py` 的 `ReportBuilder` 版型（`_slide`、`_text`），在 `build()` 的最後加一頁，標題預設為「{系所}總結與建議」。文字太長時縮小字級，或分成兩頁。
- **錯誤處理**：沒有設定 key、網路不通、額度用完或被拒絕時，在網頁上用白話顯示原因，不影響原本的簡報下載。
- **網路**：使用者確認校內網路可以連到 Claude API，不需要代理設定。

## 8. 目標與非目標

**目標**
- A：每個系所的簡報最後一頁有一段潤飾過、可以直接交給長官的總結。
- B：每次分析可以下載一份全院總結。
- 有前期資料時，自動說明進步與退步，比較對象可以改選。

**非目標**
- 不讓 AI 修改任何指標數字或排名。
- 不做聊天、問答功能。
- 不分析外部上傳的任意簡報，只處理系統自己產生的分析結果。
- 不自動把產出寄給任何人。

**反目標（技術上做得到也算失敗的情況）**
- 文字語氣尖銳，或直接批評系所。
- 引用了簡報上沒有的數字，或數字與簡報不一致。
- 把比較基準不同造成的差異，寫成系所本身的進步或退步。
- AI 服務出錯時，連帶讓原本的簡報無法下載。

## 9. 留給實作者決定

- 提示的實際文字與資料格式（JSON 或表格文字），以及是否使用 structured outputs 拆成「總結 / 與前期比較」兩段。
- 文字的資料表結構與 alembic migration（建議新增一張表，記錄 run_id、類型 A/B、系所、比較對象 run_id、內容、是否人工修改、產生時間、使用的模型）。
- 總結頁的版面細節。
- 是否加上 prompt caching（各系所共用的系統提示可以快取）。
- 測試方式：Claude 呼叫一律用假的回應（mock），比照現有的 `tests/live` 慣例，真的呼叫 API 的測試預設不執行。
