# 員額小組論文指標自動化系統

國立中央大學研發處「產製員額小組論文資料」的自動化工具。系統依人工維護的系所對照表（mapping 表），透過 Elsevier 官方 API 取得中大各系所與對標學校的論文資料，計算師均等指標並排名，再產出簡報與表格。

> **目前狀態：第一版已實作（管理學院試辦）。** 排除自我引用的 API 參數尚待驗證，報告上會標示「待驗證」。設計細節見 [docs/superpowers/specs/2026-10-30-research-benchmarking-design.md](docs/superpowers/specs/2026-10-30-research-benchmarking-design.md)。

## 功能

- **匯入 mapping 表**：自動檢查缺漏與格式問題，並顯示與上一版的差異
- **匯入教育部教師數**：可以逐筆修改，修改時記錄原因
- **自訂比較範圍**：對標學校比較、院內比較、自訂單位
- **自動抓取資料**：使用 Scopus Search 與 SciVal Publication Metrics API；請求並行、自動限速與重試，抓過的資料會快取
- **計算指標**：總篇數、Q1、Top 1%、Top 10%、FWCI、平均被引次數、國際合著，以及各項的師均與排名
- **異常標示**：查無資料或數字異常時標為「待人工確認」，不會當成 0
- **產出**：網頁表格、每個系所一份簡報（pptx）、每次分析一份 Excel（xlsx）
- **版本管理**：每次分析都會保存，記錄資料取得日期、資料來源、指標重要性，也可以比較兩個版本

## 系統需求

- Windows 10 / 11
- Python 3.11 以上
- **校內網路或學校 VPN**（Elsevier API 只能從校內使用）
- Elsevier API Key（開發階段使用小組的測試帳號，正式使用時改用承辦人的個人帳號）

## 安裝與啟動

1. 複製設定檔範本，填入 API Key：

   ```
   copy .env.example .env
   ```

   ```ini
   ELSEVIER_API_KEY=你的 API Key
   # 在校外使用時才需要
   ELSEVIER_INSTTOKEN=
   ```

2. 雙擊 `start.bat`。第一次執行會自動建立 Python 虛擬環境並安裝套件，完成後會自動開啟瀏覽器（`http://127.0.0.1:8000`）。

`.env` 和 `data/` 目錄都不會進入版本控制，請勿把 API Key 寫進其他檔案。

## 使用流程

1. **匯入 mapping 表**：到「Mapping 管理」上傳最新的 `中大與他校mapping表.xlsx`，確認檢查結果沒有錯誤
2. **匯入教師數**：到「教師數」上傳教育部的下載檔（見下方「教師數檔案」）；對應不到的系所需要手動指定，有特殊狀況的數字可以直接修改
3. **新增分析**：選擇期間（預設為前 5 年）、學院或系所、比較範圍，以及要納入的對標學校，預覽查詢條件後執行
4. **確認結果**：在結果頁查看各指標的表格與排名，逐一處理「待人工確認」的項目，並補充版本備註
5. **下載產出**：下載各系所的簡報和整份 Excel；所有歷史版本都可以在「版本紀錄」中回看

## Mapping 表格式

一間學校一個分頁，**中大自己的系所英文名稱放在「中央」分頁**。每個分頁的欄位如下：

| 學院 | 中大系所 | （學校名） | 系所中文名稱 | 系所英文名稱 | 備註 |
|---|---|---|---|---|---|
| 管理學院 | 資訊管理學系 | 管理學院 | 資訊管理學系 | Department of Information Management, National Taiwan University | |
| 管理學院 | 經濟學系 | x | x | x | |

- 第 1～2 欄是中大的學院與系所，系統用這兩欄對應各校分頁
- 「系所英文名稱」就是 Scopus 的查詢條件，需要和 Scopus 上的單位名稱一致
- 填 `x` 或留空表示該校沒有對應的系所，不列入對標
- 建立新系所時，建議先在 Scopus 網頁上用同樣的英文名稱查詢，確認篇數一致後再使用

## 教師數檔案

從[教育部大專校院校務資訊公開平台](https://udb.moe.edu.tw/udata/DetailReportList/%E6%95%99%E8%81%B7%E9%A1%9E)下載「教 1-1. 專任教師數-以「系(所)」統計」的 xlsx，直接上傳即可，不需要整理。

- 一個檔案包含多個學年度，匯入一次就好，建立分析時再選學年度（預設為最新的學年度）
- 預設採用「專任教師數-教師總數總計」欄位，可以在設定中更改
- 系統依「學校對照」（例如 台大 → 國立臺灣大學）和系所名稱自動對應；對應成功後會記住教育部的單位代碼，之後的學年度自動沿用
- 對應不到的系所，由你從該校的單位清單中挑選，可以選多個（人數相加）
- 任何一筆教師數都可以直接修改，修改時需填寫原因，報告註腳會註明來源

## 指標與計算方式

| 指標 | 計算 | 重要性 |
|---|---|---|
| 論文總篇數師均 | 5 年篇數 ÷ 5 ÷ 單年教師數 | QS、THE |
| Q1 師均 | CiteScore 前 25% 期刊篇數 ÷ 5 ÷ 單年教師數 | 高教深耕 |
| Top 1% 篇數師均 | 被引數達全球前 1% 的篇數 ÷ 5 ÷ 單年教師數 | THE、高教深耕 |
| Top 10% 篇數師均 | 被引數達全球前 10% 的篇數 ÷ 5 ÷ 單年教師數 | THE |
| FWCI | 逐篇 FWCI 平均 | THE、高教深耕 |
| 平均論文被引次數（排除自我引用） | 被引數 ÷ 總篇數 | QS |
| 國際合著篇數師均 | 國際合著篇數 ÷ 5 ÷ 單年教師數 | QS、THE、高教深耕 |

- Scopus 查詢限定 Country/territory = Taiwan，包含所有文獻類型
- Q1 指 CiteScore 期刊排名前 25%
- 排除自我引用的結果與 SciVal 網頁相同：以單位論文建立 Publication Set、Citation Count 取消勾選「Include self-citations」時，SciVal 只排除「這組論文彼此之間的引用」。系統先取得含自我引用的被引數，再減去單位論文之間的互相引用（每篇論文的參考文獻由 Scopus Abstract Retrieval 取得，每篇 1 次請求、永久快取）
  - SciVal API 的 `includeSelfCitations=false` 對逐篇指標沒有作用（已驗證），不要選用；可在「設定」切換策略
- 期間不可包含今年，起始年不可早於 10 年前（SciVal API 的限制）
- 教師數使用單一年度的人數，不是 5 年總和
- 所有數字四捨五入到小數第二位

## 開發

```
python -m venv .venv
.venv\Scripts\activate
pip install -e ".[dev]"
pytest
```

需要實際呼叫 API 的測試預設不會執行，在校內網路下設定 `RUN_LIVE_API_TESTS=1` 後才會執行：

```
set RUN_LIVE_API_TESTS=1
pytest tests/live -v
```

`api_test/output/` 中錄下的回應含有 API Key，只能用 `python scripts/sanitize_fixture.py <輸入> <輸出>` 轉成測試資料，不要直接複製。

## 計畫經費（經分表）

到「計畫經費統計表」上傳計畫管理系統匯出的「計畫基本資料」xlsx（第 1 列為區塊標題、第 2 列為欄位名稱）。匯入後，簡報會多出第 I 部分「國科會及產學計畫經費年平均」（範例第 3 頁），論文指標順延為 II、III；Excel 會多出「計畫經費」與「計畫經費明細」工作表（明細附經分表列號，方便核對）。

| 欄位 | 計算 |
|---|---|
| 國科會件數、國科會年平均 | 計畫主類為「國科會計畫」的件數與經費總額，加總後 ÷ 年度數 |
| 產學年平均 | 計畫主類為「產學合作計畫」的經費總額，加總後 ÷ 年度數 |
| 加總 | 國科會年平均 + 產學年平均 |
| 單年教師數 | 與論文指標相同（教育部公開資訊平台） |
| 師均經費 | 加總 ÷ 單年教師數 |

- 以「計畫主持人主聘單位二級」對應中大系所（財經系報告註明以主持人主聘單位計算）；技術服務收入、聯合研發中心等其他主類不計入
- 年度使用經分表的「年度」欄（民國年），分析期間 2021–2025 對應 110–114 年度
- 可以分年度上傳多個檔案，同一年度以最後匯入的檔案為準；期間內缺少的年度會在簡報註腳標示，年平均只除以有資料的年度數
- 沒有匯入經分表時，簡報維持原本的內容與編號

## 全校、全院分析與 API 限速

一次分析很多單位時，SciVal 可能回應 HTTP 429（請求太多）。系統的緩衝做法：

- **同時處理的單位與請求有上限**（設定「同時請求數上限」，預設 4），其餘排隊，不會一次湧入
- **遇到 429 時所有請求一起暫停**：依回應的 `Retry-After` 等待（沒有時以指數退避加隨機抖動），並把速度減半；連續成功後逐步恢復到設定值
- **429 有獨立的重試次數**（預設 8 次，單次最多等 120 秒），不會因為一般錯誤的重試次數用完就放棄
- **額度用完時直接停止**：回應顯示額度歸零且要很久才重置時，不白白重試，直接顯示重置時間
- **SciVal 大批次逾時或伺服器錯誤時自動拆半重試**，成功的部分立即存下
- 仍然失敗的單位會保留已抓到的資料，稍後按「繼續」即可接著抓；已抓過的論文當天不會重複消耗額度

若仍常被限速，可在「設定」調低「每秒請求數」或「同時請求數上限」。
